## ㊚ 最終動作の直前に状態を取り直す

| 構成要素 | 実装 | ギャップ |
| --- | --- | --- |
| 候補を作った時点の宛先・件名・本文と、受信スレッドの宛先ハッシュを保存する | `storeSnapshot`。キーは `snapshot:<id>`。24時間で消える | KV が無い環境では保存できない。その場合は送信しない |
| 送信の直前に、保存と受信スレッドを取り直す | `compareSendState` と `send_reply`。宛先は `email_threads` の Reply-To / From だけ | プロンプトやカードに打ち直した宛先では送らない。Gmail は userinfo で差出人も取り直す |
| 件名か本文が保存と違う、または宛先ハッシュが変わったら送らない | 理由は `state_mismatch`。`reconfirm: true` | もう一度「送信」を押すと、取り直したスレッドの宛先へ、編集後の文面を送る |
| 人がカードの「送信」を押したときだけ送る | `userApproved` と、モデルに返さない `sendNonce`。ツールの可視性は `app` | 高リスクは確認チェックも必須。下書きはアプリの KV だけで、Gmail の下書きにはしない |

不一致のとき、カードは「宛先か受信メールの状態が変わったので、内容を確認してもう一度送信を押してください。」と出します。送信に成功するまで、ツールの文面は「このメールは未送信です。」から始まります。
